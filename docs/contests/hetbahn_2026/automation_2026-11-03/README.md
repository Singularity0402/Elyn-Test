# 햇반 자동 검증
## 실행
검증실행.cmd를 한 번 실행한다. 결과는 reports/latest.html 또는 reports/latest.md에서 본다. 이 실행은 게시·접수를 대신하지 않는다.

다음을 순서대로 자동 수행한다.
1. 고정 기준·120개 규칙·기존 검토의 대상 파일을 대조한다.
2. 공식 폼을 다시 읽고 문항 정의·설명 글자 제한·필수 표시의 변경을 확인한다.
3. 실제 이미지·생성원본·로고 전체 적용 픽셀·문구 경계·고지 대비·24절기를 검사한다.
4. 새 자료를 자동 등록하고 QA·오염·잘못된 해시·충돌 응답을 제외한다.
5. 정상 최초/24시간 후속 기록을 병합하고 원답·코딩·출처 검토를 연결한다.
6. 오류 주입 테스트와 실제3초 브라우저 도구 검사를 수행한다.
7. 같은 실행의 결과·그림·설명·확인된 실제 제작 화면을 묶고,압축 손상과 파일 해시를 다시 확인한다.

검사에서 실제 실패가 나면 통과·제출준비 판정을 막는다. 자료가 부족하면 대기 상태를 유지한다. 단순 조회 실패와 확인된 기준 불일치도 구별한다.

## 새 자료를 넣는 곳
- 관객 수집기가 내려준 JSON: inputs/inbox/responses
- A/B의 실제 제작 화면: inputs/inbox/captures/A 또는 B
- 내용·출처 검토 기록: inputs/inbox/reviews
- 플랫폼 원자료 JSON: inputs/inbox/metrics
- 독립 장기 반응 기록: inputs/inbox/history

위 폴더에 넣고 같은 실행을 하면 파일 목록을 손으로 고치지 않아도 된다. 캡처는 원본을 별도로 복사해 보존한다. 입력 파일 등록만으로 화면 진위나 실제 사람 여부를 승인하지 않는다. 검토가 필요한 항목은 로컬 실행 이력의 review_queue_private.json에 생성된다. 검토 기록의 형식은 inputs/README.md에 있다.

공개 SNS·드라이브 주소와 실제 공개 열람 확인 기록은 inputs/submission.json에서 관리한다. 처음 실행할 때 빈 예시에서 만들어지며,공개 접근을 확인하기 전에는 제출 준비로 승인하지 않는다.

## 판정의 의미
- 내부 검수 완료: 파일·기준·문구·도구·오류 방지 검사가 모두 통과.
- 제출 준비 완료: 내부 검사와 공식 요강,실제 제작 화면·공개 게시물·드라이브 열람 확인을 충족.
- 외부 연구 관측 완료: 실제 관객·지연 회상·확산·비교·장기 반응 자료를 확보.긍정적인 효과와 별도.
- 수상 결과: 실제 결과를 관찰하기 전까지 확정하지 않는다.

장기 반응을 기다리느라 규정상 가능한 접수까지 막지 않는다. 외부 연구 항목은 그대로 추적한다.

## 결과와 개인정보
reports/latest.json은 공개 가능한 검증 요약이다. 원답과 상세 검토 요청은 입력함·로컬 실행 이력에 보존하며 Git 및 공개 묶음에서 제외한다. reports/현재작품_검증자료.zip에는 실제 파일과 해당 실행의 요약만 포함한다. 로고 독립 원본과 글꼴 파일은 포함하지 않는다.

공식 로고 검수 원본은 .private 캐시에만 보관한다. 캐시가 없으면 공식 URL에서 받아 고정 해시를 확인한다. 다른 파일로 바뀌었으면 자동 승인하지 않는다.

## 실행 환경
현재 로컬 PC의 Python3·Node.js·번들 sharp/Playwright·Chrome을 사용한다. 새 컴퓨터에서는 의존 경로를 확인해야 한다. 네트워크가 없는 진단은 python run_checks.py --offline으로 실행할 수 있지만,공식 안내의 최신 확인까지 끝났다고 표시하지 않는다.

코드0은 제출 자료 검사 통과,코드2는 필수 증거 대기,코드1은 실패다. 코드0도 실제 게시·폼 접수·수상 완료를 뜻하지 않는다.
