## 0. 이 보강 모듈을 쓰는 법

1. **형식은 v1과 같다.** `ID | 규칙 | 이유(원리·작가) | 점검 방법 | 깨도 되는 경우`. 점검 방법은 초고나 작업 기록을 보고 "지켰다/어겼다"를 가를 수 있게 썼다. 판정할 수 없는 문장은 규칙에서 뺐다.
2. **예외 메모는 v1과 같다.** 규칙을 깨면 `[예외: ID / 이유]`를 남긴다(RV-18). 단 **OG 규칙은 예외 메모로 깰 수 없다.** OG의 '깨도 되는 경우' 칸에 적힌 경우만 허용한다.
3. **인용 정책.** 이 문서도 원작 문장을 인용하지 않는다. '이유' 칸은 해당 작가의 작법·작품에서 필자가 추출한 원리 요약이며, 필자가 넓힌 부분에는 "(확장)"을 붙였다.
4. **적용 범위.**
   - NF는 2030년 전후 근미래, 기술이 일상을 바꾸는 이야기에 쓴다. 2050년처럼 먼 미래 과제에는 NF-01, NF-28의 연도 기준만 바꿔 적용한다.
   - OG는 장르와 상관없이 **모든 공모전 응모 원고**에 쓴다.
5. **법률 정보의 한계.** OG의 법 관련 항목은 저작권법 원리를 실무 점검 문항으로 옮긴 것이고 법률 자문이 아니다. 분쟁 가능성이 실제로 생기면 한국저작권위원회 상담이나 변호사 자문을 받는다(OG 6장 대응 절차).

| 6. 목록 갱신 | 이번에 걸린 유형(예: AI가 특정 명대사를 변형함)을 OG-18 범주나 검색어 목록에 더한다. | 목록에 1줄이 추가되었다. |

**B. 제출한 뒤, 발표 전에 발견했을 때**

1. A의 1~2단계를 한다.
2. ④~⑤ 층위 겹침이거나 4요소 3개 이상 겹침이면 주최 측에 **스스로 알리고 응모 철회를 요청한다.** 숨기고 결과를 기다리지 않는다. 수상 뒤에 드러나면 취소·환수·공개 논란으로 커지기 때문이다.
3. ③ 층위 이하이면 작업 기록과 선행작 검색 로그를 정리해 두고, 공고가 수정본 교체를 허용하면 교체를 문의한다.

**C. 수상 뒤에 의혹이 제기되었을 때**

1. 공개 대응 전에 사실관계를 정리한다: 지적된 작품, 지적된 구절·요소, OG-56 층위.
2. 작업 기록(OG-45)을 시간순으로 묶는다: 기획서 날짜, 버전 기록, 선행작 검색 로그(그 작품을 검색으로 확인했는지, 언제 확인했는지), AI 사용 기록.
3. 주최 측에 먼저 알리고 기록을 제출한다. 감정적 반박이나 상대 작가 비난을 공개적으로 하지 않는다.
4. ④~⑤ 층위 겹침이 확인되면 수상 반납 의사를 밝힌다. ①~③ 층위라면 아이디어/표현 이분법 근거와 작업 기록으로 독자 창작을 설명한다.
5. 법적 분쟁 가능성이 생기면 한국저작권위원회 상담이나 변호사 자문을 받는다. 이 매뉴얼은 법률 자문을 대신하지 않는다.

## 3. v1 규칙과의 충돌과 우선순위

OG는 v1 우선순위표의 **0등급(외부 규정)** 에 넣는다. NF 가운데 NF-41, NF-46(배점·부속 요건)도 0등급에 준하고, 나머지 NF는 v1의 해당 등급(명료성, 인과, 절제 등)에 들어간다.

| 충돌 | 결정 |
|---|---|
| v1 PR-16·FT-04의 "오마주임을 밝힌 작품" 예외 대 OG-16 오마주 금지 | 공모전 응모 원고에서는 OG-16이 이긴다. v1의 오마주 예외는 공모전 원고에서 정지한다. 공고가 2차 창작을 허용할 때만 v1 예외를 쓴다. |
| v1 WB-22(기술은 원리 대신 사용 감각과 고장으로) 대 NF의 정확한 수치·명칭(NF-21~24), 제안서형의 기술 표(NF-46) | 둘 다 지킨다. 정확성은 표와 출처 기록이 맡고, 본문은 WB-22를 따른다. 본문의 원리 설명은 기술 관련 문장의 4분의 1 이하(NF-25), 장면당 수치 2개 이하(NF-22). |
| v1 C0-10·EM-10·OE-12(결말은 교훈이 아니라 이미지) 대 정책·제안서형 공모전의 '사회적 파급'·'제안 내용' 요구 | 제안 내용은 본문 결말이 아니라 기술 표와 기획 의도 칸(NF-46)에 둔다. 서사 결말은 v1대로 이미지로 끝낸다. 공고가 본문 안에 제안 서술을 요구하면 0등급(외부 규정)이 이기며, 이때도 파급 장면(NF-45)으로 먼저 보이고 서술은 뒤에 짧게 둔다. |
| v1 PR-02(사변적 전제는 하나) 대 제안서형 공모전의 여러 기술 요구 | 기술 여러 개를 하나의 서비스로 묶어 전제 1개로 센다. 나머지 기술은 '세계 기본값'으로 분류하고 표에만 둔다(NF-30 예외). |
| 딕식 현실감 흔들기 대 공모전 낙관 톤(체임버스, NF-52) | 공고나 주최 성격이 낙관·희망을 요구하면 NF-40을 따라 흔들림을 결말 전에 확인·검증 행동으로 닫는다. 장르 SF·순문학 공모전이고 톤 지정이 없으면 v1 CT-07에 따라 열린 불안을 허용한다. |
| 깁슨식 실존 브랜드·사물의 질감 대 OG-52~53(실존 기업·상표 규칙) | 실존 브랜드는 중립 소품으로만 쓰고, 이야기에 영향을 주는 기업·서비스는 가상 명칭으로 만든 뒤 KIPRIS·웹 검색을 거친다. 부정적 역할은 언제나 가상 기업이다. |
| v1 WB-17(세계 고유 일상 디테일)·SF-07(배경 디테일: 간판, 안내 방송, 화면 속 뉴스) 대 OG-14·OG-15(실존 문구·문서 형식 흉내 금지) | 디테일은 쓰되 모든 문구를 새로 짓고 정확 일치 검색을 한다. 실존 기관 안내 방송이나 문서 양식을 그대로 흉내 내지 않는다. |
| v1 IN-19·WB-12(신조어는 꼭 필요한 것만, 첫 장 2개 이하) 대 NF-23(줄임말·별칭 권장) | 별칭도 신조어로 센다. NF-30의 '서비스명 2개 이하'와 합쳐 첫 장 신조어 2개 이하를 지킨다. |
| v1 PR-24 예외(전제가 배경일 뿐인 장르) 대 NF-57(기술 연관성 깊이 테스트) | 기술 연관성 배점이 있는 공모전에서는 PR-24 예외를 쓰지 않는다. NF-57을 통과해야 한다. |
| v1 KR-05의 김훈 1구절 직접 인용 대 OG-05(원고 인용 금지) | 충돌하지 않는다. KR-05의 인용은 매뉴얼 안의 설명이다. 그 구절을 원고에 쓰면 OG-05 위반이다. |
| v1 0장의 "작가 귀속 원리" 사용 대 OG-22(작가 스타일 프롬프트 금지) | 매뉴얼의 원리나 규칙 ID를 지시하는 것은 허용(OG-22 예외)한다. "○○처럼 써라" 같은 문장 모방 지시만 금지한다. |
